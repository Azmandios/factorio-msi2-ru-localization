## Технические решения

1. **Форма поставки — отдельный мод-перевод** `msi2-ru-localization` с единственным содержимым
   `locale/ru/*.cfg`. Оригинал не патчится и не копируется.
2. **Переопределение строк оригинала работает через порядок загрузки.** Мод-перевод объявляет
   `Mining-Space-Industries-II` обязательной зависимостью (и `?`-зависимости на остальные
   переводимые моды), поэтому грузится позже и его `locale/ru` перекрывает `locale/en` оригинала.
   Строки локали загружаются в порядке зависимостей, последняя загруженная побеждает.
   **Проверено экспериментально 2026-11-10** на этой машине: тестовый мод с `locale/ru` перекрыл
   `technology-name.laboratory` и `item-name.msi_container` из MSI2 и `entity-name.crash-site-lab-broken`
   из `factorio-crash-site`, при этом базовая игра осталась русской (`iron-plate` → «Железная плита»),
   а неперекрытые ключи остались английскими (`crash-site-generator` → «Electricity generator»).
3. **Хардкода пользовательских строк в MSI2 практически нет.** Сквозной скан 23 Lua-файлов (8 425 строк)
   нашёл всего 2 английские строки, и обе — технические ошибки (`!MSI ERROR! no valid surface...`,
   `Map setting error: minimal map size is...`), не игровой текст. Значит локали достаточно, форк не нужен.
4. **Автопроверка без запуска игры.** `factorio --dump-prototype-locale` с временным `config.ini`
   (`locale=ru`, свой `write-data`) отрабатывает за ~2 секунды и выдаёт JSON с уже разрешёнными
   названиями прототипов. Это даёт объективный признак «перевод применился»: `iron-plate` → «Железная плита»,
   а `laboratory` из MSI2 сейчас остаётся «Laboratory».
5. **Ключи `[labels]` уникальны для MSI2** (проверено по всем установленным модам), поэтому переопределение
   не заденет другие моды. Ключи `[item-name] railgun`, `computer`, `small-plane`,
   `[ammo-category-name] railgun` из `factorio-crash-site` общие с base — переводим официальными
   русскими названиями, чтобы не разъехаться с базовой игрой.
6. **Обновления оригинала.** Исходные `en.cfg` фиксируются снимком с хэшем в `tools/source/`, поэтому
   новая версия MSI2 даёт точный список добавленных/изменённых ключей, а не сплошную вычитку.

## Риски и как их снимаем

| Риск | Снятие |
|------|--------|
| Опечатка в ключе или потерянный `__1__`/`[img=...]` ломает строку в игре | `tools/check.py`: паритет ключей, мультимножество тегов и плейсхолдеров, запрет лишних ключей |
| Термины разъезжаются между файлами | `docs/glossary.json` + автопроверка запрещённых вариантов |
| Переопределение не сработало (порядок модов) | `make smoke` проверяет реальные разрешённые строки через `--dump-prototype-locale` |
| Длинные тексты миссий теряют смысл при переводе | Перенос абзацев и `\n` сохраняются, смысловые сверки по `pt-BR` и глоссарию |
| Обновление MSI2 ломает перевод | `make sync-source` + `make report --missing` после каждого обновления |

## Особые случаи

- **`[technology-name] laboratory`** — MSI2 переопределяет базовую технологию; перевод «Лаборатория»
  совпадает с официальным и ничего не ломает.

  Использовать официальные русские названия, иначе разъедется с базовой игрой.
- **Не переводить**: `MSI`, `David`, `Nauvis`, коды миссий (`MI_001`, `M_unique_*`), идентификаторы внутри
  `[img=…]`, `[item=…]`, `[technology=…]`, `[entity=…]`; `__CONTROL__informatron__` оставить как есть.
- **Числовые значения** (`0.2 - 10`, `1-normal, 5-harder`) — только пояснения, числа не менять.
- **`pt-BR`** в MSI2 — второй источник смысла там, где английская формулировка двусмысленна.
